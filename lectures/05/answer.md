### 役立った点と残る課題

**必要な根拠が早く出た例。** 11月22日に、課題文にある「第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか」をそのまま検索に使った。本文を確認し、メモリの基本を説明するp.13、Claudeでコンパクションとメモリを区別するp.39、OpenClawで保存内容を選ぶp.40を根拠とした。

| 埋め込みモデル | 第3回本講義の上位5ページ（順位順） |
|---|---|
| Gemini（配布索引） | 65 → 39 → 38 → 40 → 13 |
| E5（実験用索引） | 40 → 39 → 65 → 38 → 13 |

上位5件では、両方式ともp.13、39、40を取得できた。E5では「日々のメモのうち、基準を超えたものだけを長期メモリへ移す」と説明するp.40が4位から1位に上がった。取得を上位2件に絞る場合、p.39とp.40の両方が入るのはE5側だった。Gemini側で1位のp.65も比較の前半に関係するが、OpenClawのメモの選別はp.40が直接の根拠になる。この追加確認の計測範囲は検索順位。

**補足根拠が後ろに下がった例。** LoRAの短い検索語では、LoRAとQLoRAを直接比較するp.51がE5で2位から3位に下がり、演習手順を説明するp.61が5位から2位に上がった。p.61にもQLoRAは出てくるが、質問が求める固定対象と学習対象の違いはp.51・52のほうが直接説明している。上位2件に絞るとE5側ではp.51が外れる。実測では上位5件を渡したのでp.51も残り、両方式が根拠付きで正答した。

E5の1.95秒は今回の実測値。各方式1回であり、生成APIの応答のばらつきも含む。時間は検索と回答生成を含み、索引の構築時間は計測外。表の費用は生成APIの推定値で、埋め込みと索引構築の費用を含まない。出力トークン数も218と168で異なった。E5の512トークン上限で教材214ページ中2ページが切り詰められたが、今回確認した上位5件には、切り詰められたページは含まれなかった。

### 気づき・疑問

**LoRAでは、検索語に「何を知りたいか」を残すと順位差が縮まった。** p.51は「何を固定して何を学ぶか」を比較し、p.61はQLoRAを使った学習と、その前後の評価手順を説明する。短い検索語「LoRA QLoRA 違い」では、何についての違いかが曖昧だった。そこでE5の索引はそのままに、検索語の末尾に「固定」だけを足すと、p.51は3位から2位に、p.61は2位から3位に動いた。両ページの類似度の差は、p.61が0.0008上回る状態から、p.51が0.0065上回る状態に変わった。「学習」だけを足した場合はp.51が3位、p.61が4位だった。「何を固定し何を学習するか」まで含む元の質問文では、GeminiもE5もp.52、p.51が上位2件だった。この例では、質問を検索語に短縮するときに「固定」のような、知りたい内容を示す語を残すことで、答えの根拠を上位で拾えた。

**長期メモリでは、一つの質問文に別々の根拠が必要だった。** Geminiで1位のp.65は、質問の前半にあるコンパクションとセッションをまたぐ記録の違いを説明する。E5で1位のp.40は、質問の後半にある「日々のメモを全部残すか」に答える。E5で元の質問文の前半だけを検索すると、p.39が1位、p.65が2位、p.40は5位だった。後半だけを検索するとp.40は1位に戻り、「普段の記録はすべて次の会話でも使われますか」と言い換えても1位だった。この結果から、少なくともE5でp.40が上がったことには、質問後半の「何を次回に残すか」という意味が関係したと考えられる。二つの論点を一度に検索すると、全体の順位の中で片方の根拠が後ろに回ることがある。AIに渡すページ数を絞る場合は、論点ごとに検索して根拠をそろえる方法を試したい。

追加検証では、同じE5と同じ索引を使い、検索語だけを変えて順位を確認した。比較したページはE5の入力上限に収まっていた。モデル間の比較には、Geminiの検索用タスク指定やE5の接頭辞など、それぞれの使い方の違いも含まれる。学習データやベクトルの次元数が今回のモデル間の順位差にどの程度寄与したかは未検証。この結果から判断できるのは、今回の質問では、検索語の短縮や複数の論点を一度に検索することが、どの根拠を上位で拾えるかに影響したという範囲まで。

### 再現方法

E5のモデル配布元からONNX版の `model.onnx` と `tokenizer.json` を取得して同じディレクトリに置き、`GEMINI_API_KEY` を設定した環境で実行する。このコマンドの `AIE_RAG_DB` には未作成の実験用ファイルを指定する。配布DBは比較の基準として読み取る。[公式ONNXファイル](https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx)

```bash
AIE_RAG_DB=.cache/rag/e5-lora.sqlite3 uv run --frozen \
  --with 'onnxruntime==1.32.0' --with 'tokenizers==0.23.3' --with 'numpy==2.5.5' \
  python -m scripts.compare_embeddings --e5-dir /path/to/e5
```

第3回の質問の検索順位は、別の新規パスを指定し、同じコマンドに `--search-only` と質問文を渡して確認できる。
