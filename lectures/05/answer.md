### 気づき・疑問

11月22日はGeminiとE5に同じ11種類の検索文を入れた。214ページの本文とページ情報が両方の索引で一致することを確認し、順位付けには同じコサイン距離を使った。それぞれの索引を固定して検索文だけを変えた結果と、同じ検索文を両モデルに入れた結果を比べた。

#### LoRAの原理を探すとき、検索語に「固定」を残す効果

| 検索文 | Geminiの順位（p.51 / p.61） | E5の順位（p.51 / p.61） |
|---|---|---|
| `LoRA QLoRA 違い` | 2位 / 5位 | 3位 / 2位 |
| `LoRA QLoRA 違い 固定` | 2位 / 6位 | 2位 / 3位 |
| `LoRA QLoRA 違い 学習` | 2位 / 5位 | 3位 / 4位 |
| 元の質問文（何を固定し何を学習するか） | 2位 / 4位 | 2位 / 5位 |

「LoRA QLoRA 違い」だけでは、何の違いを知りたいのかが曖昧だった。「固定」を足すとE5でp.51とp.61の順番が入れ替わった。「学習」だけを足したときは、p.51は3位のままだった。演習手順のp.61でも学習を扱うため、「固定」のほうが原理を説明したページを探す手がかりになったと考える。Geminiでは4通りともp.51が2位だった。

p.52はどの検索文でも両モデルで1位だった。上位2件だけを使うときの違いは、p.51も一緒に拾えるかどうかにある。元の質問文をそのまま入れると、どちらもp.52とp.51が上位2件に入った。

#### 長期メモリの質問を分ける効果と、問いを並べる順番の影響

前半の問いは「第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。」、後半の問いは「日々のメモはすべて長期メモリに入りますか」。前半の根拠はClaudeの例を説明するp.39や、API機能を比較するp.65。後半の根拠は、OpenClawが残すメモを選ぶ仕組みを説明するp.40。

|---|---|---|
| 元の質問文（前半＋後半） | 2位 / 4位 / 1位 | 2位 / 1位 / 3位 |
| 前半だけ | 2位 / 5位 / 1位 | 1位 / 5位 / 2位 |

| 後半→前半（両方の文末に「。」） | 1位 / 4位 / 2位 | 2位 / 1位 / 3位 |

Geminiで4位だったp.40は、後半の問いだけを入れると1位に上がり、E5と同じ結果になった。長期保存するかを別の言葉で尋ねても、両方でp.40が1位だった。「次の会話でも使われるか」と尋ねた場合、Geminiではp.40が3位だった。この言い換えでは、メモを保存するかどうかから、次の会話で使うかどうかへと問いの焦点も少し移っている。順位の違いには、その影響も考えられる。

二つの問いの順番だけを逆にすると、Geminiではp.65とp.39の1位・2位が入れ替わった。どちらもコンパクションとメモリの違いを説明するページなので、上位で扱う論点は同じだった。E5では表に挙げた3ページの順位が変わらなかった。検索結果を少数に絞るなら、問いを一つずつ検索し、両方に答える根拠がそろうかを確かめたい。

#### 今回切り分けられたこと

順位が入れ替わったページの類似度を調べたうえで、本文中の語と埋め込みの設定を一つずつ変え、どの条件で順位が動くかを確かめた。

LoRAの短い検索語では、Geminiで原理を説明するp.51のコサイン類似度が、演習手順のp.61を0.0785上回った。E5ではp.61がp.51を0.0008上回り、ほぼ同点だった。p.61にある「QLoRA」を「この手法」に変えて、そのページだけ埋め込み直したところ、Geminiで5位から57位、E5で2位から11位に下がった。手法名は両モデルで、p.61が上位に出る手がかりになっていた。

E5で検索語に「固定」を足したとき、p.51の類似度は約0.0007上がり、p.61の類似度は約0.0067下がった。順位が入れ替わったのは、主にp.61の点数が下がったためだった。

長期メモリの元の質問文では、Geminiで前半に答えるp.65が後半に答えるp.40を類似度で0.0244上回り、E5ではp.40がp.65を0.0045上回った。p.65には前半と同じ「コンパクション」が、p.40には後半と同じ「日々のメモ」「長期メモリ」が出てくる。p.65の「コンパクション」を「履歴の圧縮」に置き換えると、Geminiでp.65は1位から3位に下がった。p.40は4位のままで、1位になったp.39も前半の問いに答えるページだった。用語の一致がp.65の順位に影響したことは確認できた。後半の根拠まで下位に回った理由は、この置き換えだけでは説明しきれない。後半だけを検索した場合は、両モデルでp.40が1位になった。元の順位差が出たのは、二つの論点を一度に検索したときである。

用語の置き換えを試す前に、元の本文でもベクトルを作り直した。保存済みのベクトルとのコサイン類似度は、表示した桁では1.00000000だった。

Geminiの質問と全214ページのベクトルを先頭384成分に絞り、順位を計算し直した。LoRAの短い検索語では、上位2件はp.52とp.51のままだった。長期メモリの元の質問文では、Geminiの1位がp.65からp.39に変わったが、後半に答えるp.40は4位のままだった。

同じ二つの検索文で、質問を埋め込むときの設定も試した。Geminiでは `RETRIEVAL_QUERY` を `QUESTION_ANSWERING` に替え、E5では `query:` を外した。どちらも元の設定と上位2件は同じだった。次元数や検索用の設定を変えると順位や類似度が動く場合はあったが、モデル間の主な順位差は残った。

技術報告では、GeminiはGemini言語モデルを、E5-smallは多言語MiniLMをもとに、異なるデータと手順で学習している。同じ文章をベクトルにしたときの近さに差が出る理由として、こうした違いが考えられる。今回の実験からは、どの学習データや内部設計が順位差に効いたかまでは特定できない。直接確認したのは、手法名や専門用語、質問に含める論点を変えると、個々のページの類似度や順位がどう動くかである。 [Geminiの技術報告](https://arxiv.org/html/2503.07891) · [Multilingual E5の技術報告](https://arxiv.org/html/2402.05672) · [Geminiの検索用タスク指定](https://aistudio.google.com/docs/embeddings#supported-task-types)

### 再現方法

E5のモデル配布元からONNX版の `model.onnx` と `tokenizer.json` を取得して同じディレクトリに置き、`GEMINI_API_KEY` を設定した環境で実行する。このコマンドの `AIE_RAG_DB` には未作成の実験用ファイルを指定する。配布DBは比較の基準として読み取る。[公式ONNXファイル](https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx)

```bash
AIE_RAG_DB=.cache/rag/e5-lora.sqlite3 uv run --frozen \
  --with 'onnxruntime==1.32.0' --with 'tokenizers==0.23.3' --with 'numpy==2.5.5' \
  python -m scripts.compare_embeddings --e5-dir /path/to/e5
```

上の二つの表にある各検索文の上位5件は、同じコマンドの末尾に `--search-only '<検索文>'` を付けて確認できる。実行ごとに `AIE_RAG_DB` に新しいパスを指定する。6位以下を含む順位は、コサイン距離が近い順に全214ページを並べて数えた。距離が同じ場合はページID順にした。
