### 気づき・疑問

11月22日、GeminiとE5の両方で同じ11種類の検索文を試した。索引に入っている214ページの本文とページ情報が一致することを確認し、両方ともコサイン距離で順位をつけた。元の配布索引とE5の実験用索引をそれぞれ固定したうえで検索文を変え、各検索文についてモデル間の順位も比べた。この追加実験では、検索順位を評価した。

#### LoRAの原理を探すとき、検索語に「固定」を残す効果

| 検索文 | Geminiの順位（p.51 / p.61） | E5の順位（p.51 / p.61） |
|---|---|---|
| `LoRA QLoRA 違い` | 2位 / 5位 | 3位 / 2位 |
| `LoRA QLoRA 違い 固定` | 2位 / 6位 | 2位 / 3位 |
| `LoRA QLoRA 違い 学習` | 2位 / 5位 | 3位 / 4位 |
| 元の質問文（何を固定し何を学習するか） | 2位 / 4位 | 2位 / 5位 |

p.51は何を固定し何を学ぶかを説明し、p.61にはQLoRAで学習して前後の結果を比べる演習手順がある。短い検索語では、比較の対象が原理なのか演習の前後なのかが曖昧だった。「固定」を足すとE5ではp.51とp.61の順序が入れ替わり、「学習」だけを足すとp.51は3位にとどまった。p.61も学習の手順を扱うので、この質問では「固定」のほうが原理を求めていることを示す手がかりになったと考える。Geminiでは4通りともp.51が2位だった。原理を説明するp.52は両モデルとも全条件で1位だったので、上位2ページに絞った場合の差は、短い検索語を使ったときにp.51まで拾えるかどうかに表れた。元の質問文では両方ともp.52、p.51を拾えた。

#### 長期メモリの質問を分ける効果と、問いを並べる順番の影響

前半の問いは「第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。」、後半の問いは「日々のメモはすべて長期メモリに入りますか」。前半の根拠はClaudeの例を説明するp.39や、API機能を比較するp.65。後半の根拠は、OpenClawが残すメモを選ぶ仕組みを説明するp.40。

|---|---|---|
| 元の質問文（前半＋後半） | 2位 / 4位 / 1位 | 2位 / 1位 / 3位 |
| 前半だけ | 2位 / 5位 / 1位 | 1位 / 5位 / 2位 |

元の質問文ではGeminiが1位にしたp.65は前半に、E5が1位にしたp.40は後半に答える。検索を後半だけに絞ると、両モデルともp.40が1位になった。長期保存するかを別の言葉で尋ねた場合も両方で1位だった。「次の会話でも使われるか」と尋ねるとGeminiではp.40が3位に下がった。この文では保存から次回の利用へと問いの焦点も少し移るので、語の置換だけの影響としては扱えない。

両方の問いを残し、文の順序だけを逆にすると、Geminiではp.65とp.39の1位・2位が入れ替わった。両ページとも前半を説明するので、どちらの論点が優先されたかは、この入れ替わりだけでは変わらなかった。E5では表の3ページの順位が同じだった。検索結果を少数に絞る場合は、各論点を個別に検索して、両方に答える根拠がそろうかを見たい。

#### 今回切り分けられたこと

同じ書き換えをしても、順位の動き方にはモデル間で差があった。そこで、順位が逆転したページの類似度を調べ、ページ本文と埋め込みの設定を一つずつ変えた。

**LoRAの差は、演習手順が原理の説明とどれほど競り合ったか。** 短い検索語では、Geminiで原理のp.51のコサイン類似度が演習手順のp.61を0.0785上回った。E5では逆にp.61がp.51を0.0008上回り、ほぼ同点だった。p.61の「QLoRA」を「この手法」に置き換え、そのページだけ埋め込み直すと、p.61はGeminiで5位から57位、E5で2位から11位に下がった。演習ページが候補になることには、両モデルで手法名の記述が効いていた。E5で検索語に「固定」を足すと、p.51の類似度は約0.0007上がり、p.61の類似度は約0.0067下がった。E5での順位逆転は、主に演習ページとの近さが下がったことで起きた。

**長期メモリの差は、二つの問いを同時に入れたとき、どちらに答えるページが上がったか。** 元の質問文では、Geminiで前半に答えるp.65が後半に答えるp.40を類似度で0.0244上回り、E5ではp.40がp.65を0.0045上回った。p.65には前半と同じ「コンパクション」が、p.40には後半と同じ「日々のメモ」「長期メモリ」が出てくる。p.65中の「コンパクション」を「履歴の圧縮」に置き換えると、Geminiでp.65は1位から3位に下がった。p.40は4位のままで、前半に答える別のページ（p.39）が1位になった。質問との用語の一致は、p.65が1位になることには影響したが、後半の根拠が下位に来たことまでは説明できない。後半だけを検索すると両モデルでp.40が1位になるため、元の差は、二つの論点を一つの検索文に含めたときに現れた。用語を置換する前の本文も埋め込み直し、配布済みまたは事前に作成したベクトルとのコサイン類似度が表示精度で1.00000000になることを確認した。

**次元数と検索用の指定を一つずつ変えても、主な差は残った。** Geminiの質問と全214ページのベクトルを先頭384成分に絞って再計算すると、短いLoRA検索の上位2件はp.52、p.51のままだった。長期メモリの元の質問文では、Geminiの1位がp.65からp.39に変わり、後半に答えるp.40は4位にとどまった。両方の検索文で、Geminiの質問側の指定を `RETRIEVAL_QUERY` から `QUESTION_ANSWERING` に変更する試行と、E5の質問側の `query:` を外す試行も行った。それぞれ元の設定と上位2件が同じだった。次元数や指定の変更で順位や類似度が動く場合はあったが、本比較で見えた優先順位の違いは、ここで試した変更だけでは再現できなかった。

公開資料では、GeminiはGemini言語モデルを、E5-smallは多言語MiniLMを出発点とし、異なる学習データと手順で関連する文章を近く置くよう学習している。こうした違いは、同じ文章をベクトルにしたときの近さが変わる理由として考えられる。今回直接確かめたのは、手法名や用語、質問に含める論点が、どのページの類似度や順位に影響したかまで。特定の学習データや内部設計がそれぞれの順位差を生んだかは、この比較では特定できない。 [Geminiの技術報告](https://arxiv.org/html/2503.07891) · [Multilingual E5の技術報告](https://arxiv.org/html/2402.05672) · [Geminiの検索用タスク指定](https://aistudio.google.com/docs/embeddings#supported-task-types)

### 再現方法

E5のモデル配布元からONNX版の `model.onnx` と `tokenizer.json` を取得して同じディレクトリに置き、`GEMINI_API_KEY` を設定した環境で実行する。このコマンドの `AIE_RAG_DB` には未作成の実験用ファイルを指定する。配布DBは比較の基準として読み取る。[公式ONNXファイル](https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx)

```bash
AIE_RAG_DB=.cache/rag/e5-lora.sqlite3 uv run --frozen \
  --with 'onnxruntime==1.32.0' --with 'tokenizers==0.23.3' --with 'numpy==2.5.5' \
  python -m scripts.compare_embeddings --e5-dir /path/to/e5
```

上の二つの表にある各検索文の上位5件は、同じコマンドの末尾に `--search-only '<検索文>'` を付けて確認できる。実行ごとに `AIE_RAG_DB` に新しいパスを指定する。6位以下を含む順位は、コサイン距離が近い順に全214ページを並べて数えた。距離が同じ場合はページID順にした。
